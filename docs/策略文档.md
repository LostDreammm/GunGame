# 《未来战争》当前策略说明

对应实现：`Demo/CoreGeek`（agent_version=1.3）

| 模块 | 路径 | 职责 |
|------|------|------|
| 入口 | `Demo/CoreGeek/main3.py`、`src/agent/server.py` | HTTP 服务；每回合接收地图快照，返回 `roleCommandMap` / `prompt` / `executeCmd` |
| 决策 | `src/agent/brain.py` | 昼夜调度、经济、建造、物品、任务与宝藏 |
| 世界与战斗 | `src/agent/grid.py` | 路径、弹道估值、炮台/围墙选址、自动建造 |
| 推理 | `src/agent/protocol.py`、`src/agent/task_loop.py` | 平台 LLM、自进化沙盒修复闭环、新闻解析、宝藏校验 |
| 配置 | `Demo/CoreGeek/config.json` | 开关与阈值，不改代码即可微调 |
| 测试 | `Demo/CoreGeek/tests/test_strategy.py`、`tests/test_task_loop.py` | 布局/夜间/经济，以及自进化修复与 SOP |

策略只使用判题器每回合下发的观察，不依赖本地模拟器或本地模型。平台 LLM 与沙盒命令通过响应字段异步发出，下一回合再读 `llmResp` / `lastCmdResult`。

坐标按任务书：原点在地图左下，`+x` 向右，`+y` 向上。基地 `pos` 是 2×2 占地的**左上格**。

---

## 1. 总方针

1. **三座指定火箭，一人轮流操控。** 炮位由基地左上格 `(x, y)` 直接算出；开拓者夜间在炮之间轮转，工人夜间继续采集。
2. **12 块 C 形围墙朝向敌方。** 左上基地墙在右侧，右下基地墙在左侧；转角共享，去重后恰好 12 格。摧毁后优先原位重建。
3. **先凑建墙石头，墙满再挖高价矿。** 缺口以外的石头才许出售；当天剩余回合不够走完「采集 + 去小贩 + 出售」就不出发。
4. **修复包囤到 5 个。** 低于 5 就补，满了停买；紧急维修优先于一般经济。
5. **升级顺序随基地血量调整。** 默认武器 → 围墙 → 基地；基地血量低于上限 50% 时改为武器 → 基地 → 围墙。
6. **任务与宝藏只走有证据的路径。** 先锋不在危急时出门；宝藏必须有新闻原文支撑，禁止盲探。

## 2. 回合状态与时间

### 2.1 跨回合记忆

同一场比赛内保留：失败格、移动失败计数、矿点产量、昨夜峰值伤害与兵种构成、建筑血量上限、当日召唤次数、已尝试的宝藏、**规划好的 12 个墙位**、**曾经见过墙的格子**（用于原位重建）。

以下情况整场重置：阵营/`teamId` 变化，或 `roundNo` 回退（新对局）。同一 `roundNo` 的重复 HTTP 请求直接返回缓存指令。

动作反馈晚一回合。仅当本回合 = 上一决策回合 + 1 时，才根据 `lastRoundRoleActionResults` 更新：

- `collect` / `build` 失败：把目标格加入失败表，约 4 回合后再试。
- `move` 失败：回防余量加重；成功则逐步恢复。
- `collect` 成功：累计该矿点产量（矿区无剩余次数字段，只能用自己的成功采集次数估计枯竭）。

### 2.2 昼夜划分

`phase = roundNo - round_origin`（配置默认 `round_origin=1`；若观察到 `roundNo=0` 则自动改为 0）。

- 一天 130 回合，白天 70、夜晚 60。
- `day = phase // 130 + 1`
- `night`：当天已过 70 回合
- `remaining_day`：白天剩余回合（开拓者回炮仍用这个）
- `remaining_cycle`：当天整段还剩多少回合，含即将到来的夜晚。工人采集/出售按这个判断，因为夜间仍可去小贩。

开拓者回防余量 = `return_margin`（默认 4）+ `min(4, 移动失败计数)`。工人入夜不召回。

## 3. 安全模式

用「基地当前血量 / 预估夜压」得到安全比。夜压下限为 200，避免开局误判为绝对安全。

| 夜间 | 白天 |
|------|------|
| 未来 15 回合内、朝我方推进的机器人预计对基地伤害 | 昨夜峰值伤害 × 1.25 |

机器人路径与锁定目标接口不提供，伤害是可观察代理值：距离基地 Chebyshev 距离、剩余夜晚、`targetTeam`、眩晕各算一档；已确认打对面的单位不计。

| 安全比 | 模式 | 行为 |
|--------|------|------|
| `< 1.2` | `critical` | 先锋不接任务、不探宝；更早吃药；邻格优先用墙修 |
| `< 1.8` | `defensive` | 夜间可用炸弹/眩晕；接任务额外预留 4 回合 |
| 其余 | `reward` | 正常探险与经济；夜间默认不用范围道具 |

紧急生存（吃药、贴身修墙、工人被机器人贴住）优先于一般经济，但不改变长期布局：三火箭、12 墙、修复包 5、高价矿。

## 4. 每回合决策顺序

```
观察世界（昼夜、波次、墙位、石头缺口、修复包库存、基地血量比）
  → 更新 Reasoning（新闻 / 任务 LLM）
  → 若已有 phaseTask：先锋本回合提交答案
  → 全员先处理紧急物品 / 范围道具 / 邻格升级与修墙 / 召唤
  → 夜晚：至少一名角色留在炮位开火（优先开拓者；开拓者在做题或不在时由最近工人顶上）；其余工人继续采集
  → 白天：
        先锋：天黑前赶回炮位，否则任务/宝藏 → 购物 → 回炮
        工人：若先锋赶不回则一人提前回防；其余建造 → 按缺口采石 → 挖矿 → 当天能完成则出售 → 购物
```

每个人每回合最多一条指令。药品、升级券、炸弹、召唤令都会占掉该角色本回合，因此先于开火与建造处理。

## 5. 炮台布局

武器只能建在内环蓝格（基地 4×4 去掉 2×2）。默认三座火箭，每座 25 金。

用基地中心相对地图中心判断区域：偏左且偏上为左上，偏右且偏下为右下。`(x, y)` 是基地 2×2 的左上格。

| 基地位置 | 指定 3 格（相对左上格 `(x, y)`） |
|----------|----------------------------------|
| 左上 | `(x-1, y)`, `(x-1, y-2)`, `(x, y-2)` |
| 右下 | `(x+2, y-1)`, `(x+2, y+1)`, `(x+1, y+1)` |

三格都在内环蓝格上，不与 2×2 基地重叠。指定格被占或越界时，在蓝格中搜索其它可操作的 3 连格。没有合法格则本回合不建，打日志，不抛异常。角色仍走 8 方向，从围墙开口进入邻格操控。

第 1 天已有 2 座炮、白天还很长、金币不足 25 + 开局现金储备时，暂缓第三座炮，先去挖矿凑钱。

当前 `adaptive_weapons=false`，不按波次改炮种。若打开该开关，第 3 天起可在原格覆盖成缺口类型。

## 6. 围墙布局

围墙只能建在外环黄格。目标 12 块，用集合去重。坐标由当前基地位置推算。

**左上基地**（墙在右侧，开口朝左/己侧）：

- 右侧纵向 6 块：`x = sx+3`，`y` 从 `sy-3` 到 `sy+2`
- 上侧横向 4 块：`y = sy+2`，`x` 从 `sx` 到 `sx+3`（与右上角共享）
- 下侧横向 4 块：`y = sy-3`，`x` 从 `sx` 到 `sx+3`（与右下角共享）

**右下基地**（镜像，墙在左侧）：

- 左侧纵向 6 块：`x = sx-2`，`y` 从 `sy-3` 到 `sy+2`
- 上、下横向各 4 块，分别与左上/左下转角共享

预定格被占或越界时，在黄环上取最近合法替代。12 个槽位一旦选定，本场锁定；已有墙不重复建造。见过墙的格子若变空，视为被摧毁，优先在原槽位重建。

有效围墙 = 仍站在这 12 个槽位上的墙。规划外的墙不计入缺口。

## 7. 夜间角色分工

至少一名角色留在基地邻格操纵火箭开火。火箭冷却 3 回合，每角色每回合只能打一座炮：

- **值班人**：优先已站在炮旁的角色，其次开拓者，再次路径最短的工人。开拓者在做自进化任务、阵亡或不在 `available` 时，由工人顶上。
- **其余工人**：夜间继续采集；背包满且当天剩余回合够时去小贩。不因入夜把两名工人都召回。
- **白天预留**：若开拓者在天黑前赶不回炮位，派一名工人提前返回。
- **中断采集**仅当：该工人被派去值班、机器人切比雪夫距离 ≤ 1、血量 ≤ 80、或目标矿不可达。

### 7.1 开火模型（未改）

仅夜晚。控制者必须与武器相邻，且 `cooldown=0`。

| 武器 | 每回合射击数 | 命中模型（保守估计） |
|------|----------------|----------------------|
| 加特林 | 等于等级 | 射线首个机器人；同一回合多发须落在同一锥内 |
| 电磁炮 | 1 | 射线穿射，能量按血量依次扣完 |
| 火箭 | 等于等级 | 落点 20，邻格 10；可打空格溅射，不打武器自身格 |

优先打确认朝我方、靠近基地、未眩晕、攻击力高的单位。`targetTeam` 缺失时仍按距离给较低权重。

### 7.2 范围道具

仅夜间、非 `reward`、全队本回合只用一次：

- `Bomb`：估值 ≥ 180 才用
- `DizzyWeapon`：估值 ≥ 100 才用

---

## 8. 白天：建造

配置 `construction.mode` 为 `auto`。夜晚不建；只有工人建造。顺序：先补满 3 座规划火箭，再按槽位砌墙。

工人走到邻格再建。建造格避开障碍、本回合已预约格、近期失败格；建成后操作格仍须有出路。

---

## 9. 采集、出售与回合预算

### 9.1 石头缺口

```
待重建围墙数 = 12 - 当前有效围墙数 - 本回合已规划建造数
所需石头数 = 待重建围墙数 × 1
石头缺口 = max(0, 所需石头数 - 全队背包石头数)
```

缺口 > 0：优先采石头，且建墙所需石头不出售。墙满 12 后改采单价更高的矿（通常铜 > 铁 > 石）。墙被摧毁后仍先补石头缺口。

工人每次采矿都尽量把背包采满再去出售：矿点采尽就换下一个同优先级矿，不在 20 格或市值门槛处提前收工。石头缺口补完后，同一趟剩余空位继续按高价矿填满。背包满了、或已经没有可采的矿，才启动出售。建墙时先把本次缺口需要的石头一次采齐，再连续砌墙，避免「采 1 块跑一趟」。

新闻判定某矿停工的日期内，该矿不会被采集。

### 9.2 当天能否变现

完整流程回合数：

```
把背包剩余空位采满所需回合
+ 从矿点走到小贩邻格
+ 执行出售
+ 移动失败带来的少量余量
```

`剩余回合` 用 `remaining_cycle`（含夜晚）。够用则采满背包再去卖；不够则继续采集把背包填满，不启动走不完的出售。已经站在小贩旁边且背包已满（或矿已采不到）时，出售只需 1 回合，仍可当场卖掉**允许变现**的矿。

邻接小贩时，卖掉单价×数量最高的一种可售矿。收入本回合不能立刻用于购买。未邻接时，只有背包已满或强制回笼（无矿可采），且当天走得完，才出发。

挖矿在可见、未封锁、未失败的矿里，按

```
估计剩余次数 × 单价 / (去矿路程 + 剩余次数 + 矿到小贩距离 + 1)
```

挑选；有石头缺口时石头权重大幅提高。剩余次数用 `max(1, 10 - 自己在该点的成功采集次数)` 估计。单个矿约 10 次，所以一趟满背包（工人 100 格）会连续换矿，而不是采完一个矿就去卖。

## 10. 购物与升级

### 10.1 顺序

1. 背包里已有升级券 → 走到对应建筑邻格使用（任何人都能用券）。
2. 武器未满 3 座，或当天剩余不足 25 回合 → 不进店。
3. 购买升级券（每次购买前重算基地血量比 `当前血量 / 最大血量`）：
   - 正常（≥ 50%）：武器 → 围墙 → 基地
   - 低于 50%（不含等于）：武器 → 基地 → 围墙
   - 高优先级买不起或店里没有，继续试下一档
   - 同组选等级低、血量低者
4. **围墙修复包**：全队库存目标 5。少于 5 时按缺额购买；达到 5 停止。使用后低于 5 再补。不与三火箭抢关键金币：先留「缺炮数 × 25」。
5. 其它消耗品：`roundNo ≥ consumable_start_round`（默认 391）之后才考虑。

其它消耗品意向（全队库存没有才买）：

| 条件 | 购买 |
|------|------|
| 角色残血 | `Medicine` × 1 |
| 有墙血量低于上限 55% 且修复包为 0 | `WallFixer` × 1 |
| 昨夜峰值伤害 ≥ 180 | `DizzyWeapon` × 1 |
| 非 reward 且昨夜小/中型机 ≥ 6 | `Bomb` × 1 |
| 进攻条件已满足 | `MiddleRobotSummonOrder`（最多补到当日剩余召唤次数） |

防御现金缓冲：缺的武器 × 25，外加 20（reward 模式为 10）；已有墙且修复包未满时再留一张修复包的钱。

### 10.2 邻格即时使用

- 升级券：建筑等级 < 3，且（是武器 / 受损低于上限 75% / 非 reward / 已到第 8 天）时立即用。
- 墙修：邻格墙血低于上限 55% 时，修血最低的那座。危急模式下即使白天也会在邻格抢修。
- 药品：工人血上限按 220、先锋按 200；危急时 70% 以下就吃，否则 50% 以下才吃。

基地/墙/武器的「满血」用本场观察到的最大血量记忆；未见过时基地按 1500、其余按 1000。

## 11. 先锋：任务与宝藏

危急模式两者都不做，先锋回炮或回基地。白天在回炮窗口之前仍可接任务、探宝、购物。

### 11.1 接任务

只在己方任务点接。效用大致为：

```
期望得分 / (路程 + 预估解题回合)
```

期望得分考虑 `scoreReward`、超时加速分 `5 × timeout / 实际用时`、以及少量金币。已有同族 SOP 时按约 2～3 回合、成功率更高；否则用 `tasks.solve_estimate`（默认 6 回合）。必须在**白天结束前**走完「去任务点 + 解题 + 回最近炮位 + 余量」。

接到 `phaseTask` 后，先锋该回合改为 `submitAnswer`。解题交给平台 LLM（见第 13 节）。

### 11.2 宝藏

仅当 `enable_treasure=true`，且新闻模块给出通过校验的祭坛。禁止无证据试探：合法失败仍会吃掉全部祭品。

缺祭品则白天且剩余 ≥ 25 回合时先去武器店买齐（保留至少 20 金），再在开启窗口内 `summonTreasure`。一旦发出召唤，立即记入已尝试集合。

## 12. 进攻（后期可选）

同时满足才视为可进攻：

- `offense.enabled=true`
- 白天、第 `start_day` 天及以后（默认 8）
- 安全比 ≥ 1.8
- 三座武器已在场
- 可见敌方基地血量 ≤ `enemy_base_health_threshold`（默认 900）

此时角色可使用背包中的召唤令，每日最多 10 次。不主动冲敌阵。

---

## 13. 新闻与 LLM

`enable_llm=false` 时不发 `prompt`；字面规则仍会从官方新闻里抽「明日停工 N 天」这类确定关闭。

### 13.1 新闻

官方新闻 + 民间传闻变化时，每天最多分析 3 次。模型必须回 JSON：矿区关闭列表与可选宝藏。关闭证据必须是官方原文连续片段；宝藏的地点/祭品/时间证据必须是传闻原文。配额耗尽（错误码 5）当日不再请求。

### 13.2 自进化任务

任务进行中每回合二选一：沙盒 `executeCmd` 或最终 `submitAnswer`，禁止空转。选手进程不在本地跑模型或访问公网，只根据 `lastCmdResult` 分类错误并给出下一命令。

接口文档只是候选方案。若沙盒返回缺少 `Authorization`、参数名变更（如 `city`→`location`）、脚本 `bad interpreter`/CRLF/缺执行权限，本地进入可恢复修复：改请求后重试，禁止原样重复失败请求，最多 5 次。凭据只保存在内存引用里，日志和 SOP 脱敏。首个同类任务验证成功后写入 SOP/SKILL，后续城市任务先复用再验证；旧经验与真实接口冲突时更新，而不是直接当答案提交。

---

## 14. 导航约定

- 八方向移动；当前其他单位视为障碍，不做换位假设。
- 本回合已选目的地写入 `reserved`，避免对撞。
- 交互格 = 目标格的八邻域（不含目标自身）。采集、建造、买卖、用券、控制武器都在邻格完成。
- 基地占 2×2，寻路与火力距离都按这四格计算。

## 15. 代码常量与默认配置

策略里写死、测试也会核对的常量：

| 常量 | 值 | 含义 |
|------|----|------|
| `ROCKET_TURRET_COUNT` | 3 | 火箭数量 |
| `TARGET_WALL_COUNT` | 12 | 目标墙数 |
| `WALL_STONE_COST` | 1 | 单块墙耗石 |
| `WALL_REPAIR_KIT_TARGET_STOCK` | 5 | 修复包目标库存 |
| `BASE_LOW_HEALTH_RATIO` | 0.5 | 基地血量改优先级的阈值（低于才改，等于仍用默认） |

| 项 | 值 | 含义 |
|----|----|------|
| `round_origin` | 1 | 回合编号起点 |
| `enable_llm` | true | 启用平台 LLM |
| `enable_treasure` | true | 允许有证据的寻宝 |
